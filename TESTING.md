# TESTING.md

# Практическое задание №7 — Тестирование работоспособности системы

## Цель

Проверить, что ML-сервис работает как единая система и корректно выполняет основные пользовательские и бизнес-сценарии.

Тестирование охватывает:

- REST API;
- бизнес-логику;
- работу с PostgreSQL;
- асинхронную обработку через RabbitMQ;
- ML-воркеры;
- историю транзакций;
- историю ML-запросов;
- пакетную обработку частично валидных данных.

## Тестируемая архитектура

```text
REST client
    ↓
  Nginx
    ↓
 FastAPI
    ↓
PostgreSQL
    ↓
RabbitMQ
  ↙   ↘
worker-1
worker-2
    ↓
ML-модель
    ↓
 FastAPI
    ↓
PostgreSQL
```

Тестирование выполняется через REST API, при этом ML-запросы проходят полный асинхронный путь через RabbitMQ и ML-воркеры.

## Подготовка окружения

```bat
docker compose up -d
```


- `worker-2`;
- `web-ui`;
- `telegram-bot`.

FastAPI успешно прошёл healthcheck:

```text

```

## Детали ключевых проверок

### 1. Работа с пользователями

Проверены:

- создание нового пользователя;
- первая авторизация;
- повторная авторизация;
- неверный пароль;
- повторная регистрация;
- доступ к защищённому endpoint без авторизации.

Результат:

```text
Регистрация → 201
Авторизация → 200
Повторная авторизация → 200
Неверный пароль → 401
Повторная регистрация → 409
Доступ без авторизации → 401
```

## 2. Работа с балансом

После регистрации проверяется начальный баланс:

```text
0.00
```

После пополнения:

```text
10.00
```

Также проверено, что отрицательное пополнение отклоняется и не изменяет баланс.

## 3. Списание кредитов

Перед ошибочным ML-запросом баланс:

```text
10.00
```

Запрос к неизвестной модели:

```text
HTTP 400
```

После ошибки баланс остаётся:

```text
10.00
```

То же правило проверено для некорректного пустого текста.

После успешной ML-задачи:

```text
10.00 → 0.00
```

Таким образом подтверждено правило:

```text
списание выполняется только после успешного предсказания
```

## 4. ML-запросы

Обычный ML-запрос проходит полный путь:

```text
POST /predict
    ↓
202 pending
    ↓
RabbitMQ
    ↓
worker
    ↓
ML-модель
    ↓
completed
```

Во время теста задача была успешно обработана одним из ML-воркеров.

Проверяются:

- статус `pending`;
- переход в `completed`;
- наличие результата;
- корректный `worker_id`;
- класс `positive`, `neutral` или `negative`;
- списание `10.00`.

## 5. Частично валидные данные

Для проверки использовался пакет:

```json
{
  "model_name": "sentiment-model",
  "rows": [
    "Мне очень нравится этот сервис",
    "",
    123,
    "Это ужасный продукт"
  ]
}
```

Ожидается:

```text
строка 1 → valid
строка 2 → invalid: пустая строка
строка 3 → invalid: значение должно быть строкой
строка 4 → valid
```

Backend возвращает:

- две строки в `accepted`;
- две строки в `invalid_rows`.

Валидные строки создают реальные ML-задачи и проходят через RabbitMQ и workers.

Невалидные строки не создают ML-задачи и не оплачиваются.

При стоимости одного предсказания `10.00` за две корректные строки списано:

```text
20.00
```

## 6. Недостаточный баланс

После обнуления баланса повторный одиночный ML-запрос возвращает:

```text
HTTP 402
```

Баланс остаётся:

```text
0.00
```

Для batch-запроса также проверено правило:

```text
если средств недостаточно для всех корректных строк,
пакет не принимается частично
```

Результат:

```text
HTTP 402
```

Ни одна новая задача не должна быть оплачена частично.

## 7. История транзакций

История проверяется через:

```text
GET /history/transactions
```

Тест сопоставляет историю с ранее выполненными действиями.

Для тестового сценария ожидаются:

```text
2 credit-транзакции
3 debit-транзакции
```

Списания должны соответствовать:

```text
1 успешная одиночная ML-задача
2 успешные batch-задачи
```

Также проверяется соответствие `task_id` транзакций реальным успешно завершённым ML-задачам.

## 8. История ML-запросов

История проверяется через:

```text
GET /history/predictions
```

Проверено, что:

- одиночная задача присутствует в истории;
- обе batch-задачи присутствуют в истории;
- задачи имеют статус `completed`;
- результат предсказания сохранён;
- информация о списании сохранена.
